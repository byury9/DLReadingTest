# DLReadingTest

YOLO26 딥러닝 모델로 이미지 속 **영문 대문자(A-Z)와 숫자(0-9)** 를 읽는 C# WinForms 테스트 프로그램입니다.

- .NET Framework 4.8 / C# WinForms (x64)
- 추론: [ONNX Runtime](https://onnxruntime.ai) (`Microsoft.ML.OnnxRuntime`) - OpenCV 불필요
- 모델: Ultralytics **YOLO26n** 을 문자 검출용으로 학습한 ONNX (`DLReadingTest/Models/alnum_yolo26n.onnx`)

## 기능

| 기능 | 설명 |
|---|---|
| 폴더 열기 | 선택한 폴더의 이미지(bmp, jpg, png, tif, gif)를 파일명 순서로 불러옴 |
| 이미지 순환 | `▶ 재생` 시 설정한 간격(ms)마다 다음 이미지로 넘어가고 마지막 다음은 처음으로 돌아옴. `◀ 이전` / `다음 ▶` 으로 수동 이동 |
| ROI (여러 개) | `ROI 추가` 를 누르면 기본 ROI `(10+n, 10+n, 100×100)` 생성 (n = 기존 ROI 개수 × 10, 겹치지 않게 조금씩 비켜서). **테두리 선** 위에서 커서가 ✥ 로 바뀌면 드래그해서 이동, **선택된 ROI 의 모서리 네모**를 드래그하면 크기 조절, 안쪽 클릭은 선택, 빈 곳 클릭은 선택 해제. 선택된 ROI 는 노란색(+모서리 네모), 나머지는 파란색. `선택 ROI 삭제`(또는 `Delete` 키)로 삭제. ROI 가 없으면 전체 영역을 읽음 |
| 읽기 | ROI 마다 잘라서 YOLO 추론. **ROI 수만큼 작업을 동시에(병렬) 실행**하고 결과는 ROI 별로 표시 (`R1`, `R2` …, 표의 `ROI` 열). `자동 읽기` 를 켜면 이미지가 바뀔 때마다 마지막으로 누른 동작(읽기/검증)을 자동 실행 |
| 검증 | `검증할 문자` 에 인쇄 내용을 입력(줄은 공백이나 쉼표로 구분, 예: `GWTB017P 2030.03.16`)하고 `검증` → 자리마다 기대한 글자가 있는지 OK/NG 판정 ([아래](#문자-검증-ocv) 참고) |
| 결과 표시 | 이미지 위에 글자별 박스와 읽은 값을 표시(초록 ≥0.7, 주황 ≥0.5, 빨강 <0.5). 오른쪽에 줄 단위 문자열과 글자별 문자/신뢰도/X/Y/W/H 표. 표의 행을 선택하면 해당 글자가 강조됨 |
| 설정 저장 | 마지막 폴더, ROI 목록, 모델 경로, 간격, 신뢰도를 실행 폴더의 `DLReadingTest.ini` 에 저장 |
| 글자 치환 | 영문 `O` 는 쓰지 않으므로 숫자 `0` 으로 표시 (`DLReadingTest.ini` 의 `LabelMap=O:0`, 여러 개는 `O:0,I:1` 처럼 쉼표로 구분, 비우면 치환 안 함) |

단축키: `F5` 읽기, `F6` 검증(검증할 문자 입력칸에서 `Enter` 도 가능), `←/→` 이전/다음, `Space` 재생/정지, `Delete` 선택 ROI 삭제, `Esc` ROI 선택 해제

### 샘플 이미지 (`samples/`)

- `real_2025-05-28_10-12-15.bmp`: 실제 카메라 이미지 (박스 10개, 제조번호 `GWTB016P` / 사용기한 `2030.03.12`)
- `real_2025-05-28_10-09-37.bmp`: 실제 카메라 이미지 (박스 10개, 제조번호 `GWTB017P` / 사용기한 `2030.03.16`)
- `sample_01~12.png`: 실제 이미지에서 영숫자 인쇄만 지운 바탕에 다른 값을 찍은 합성 이미지
  - 01~04 정상, 05~08 움직임 번짐(가로로 글자가 끌림), 09~12 인쇄 문질림(획 일부 지워짐/번짐)
  - 정답은 `samples/answers.txt` (`training/make_samples.py` 로 다시 만들 수 있음)

박스 하나의 인쇄 영역에 ROI를 잡으면 한글 라벨(`제조번호 :` 등)을 빼고 그 박스만 읽습니다.
ROI 없이 전체를 읽으면 박스 10개를 모두 읽고, 결과는 줄 단위(왼쪽 박스 → 오른쪽 박스 순)로 나옵니다.

## 문자 검증 (OCV)

작업마다 인쇄할 내용을 알고 있으므로, "무슨 글자인가?"를 맞히는 읽기(OCR) 대신
**"이 자리에 기대한 글자가 있는가?"** 를 판정합니다. 쓸린 글자에 훨씬 강합니다.

- 모델은 글자 후보마다 36개 글자 각각의 점수를 냅니다. 읽기는 가장 높은 점수의 글자를 고르지만,
  검증은 **기대한 글자의 점수**만 봅니다. 쓸려서 `7` 이 `2` 로 읽혀도 `7` 의 점수가 남아 있으면 OK 입니다.
- 실제로 다른 글자가 인쇄되어 있으면 기대 글자의 점수는 거의 0 이 되어 NG 가 됩니다
  (예: `GWTB016P` 인쇄물을 `GWTB017P` 로 검증하면 `7` 자리 점수 0.00 → NG "다른 문자 6").
- 로직은 `Yolo/TextVerifier.cs` 에 따로 있습니다.
  1. 낮은 기준(0.05)으로 글자 후보를 넓게 검출
  2. 후보를 줄로 묶고, 간격이 크게 벌어진 곳(옆 박스, 한글 라벨)에서 끊음
  3. 기대 문자열 줄마다 가장 잘 맞는 묶음을 위에서부터 고름
  4. 묶음의 후보와 기대 문자열을 순서대로 대응 (동적 계획법: 빠진 글자, 잡음 후보 허용)
  5. 자리마다 판정: **OK**(기대 글자 점수 ≥ 기준) / **점수 낮음** / **다른 문자**(다른 글자가 0.25 이상으로 읽힘) / **글자 없음**(앞뒤 간격으로 위치를 추정해 점선 표시)
- 결과: 오른쪽 위에 `검증 OK/NG` 와 줄별 결과(`OK` 자리는 기대 글자, 다른 문자는 읽은 글자, 점수 낮음 `?`, 없음 `_`, 줄 끝 숫자는 가장 낮은 자리 점수),
  표에 자리별 점수/판정/비고, 이미지에 자리별 초록(OK)/빨강(NG) 박스.
- 줄은 공백 / 쉼표 / 줄바꿈으로 구분하고, `.` `-` `/` 등 모델이 읽지 않는 문자는 무시합니다. 영문 `O` 는 `0` 으로 봅니다(`LabelMap`).
- OK 기준은 화면의 `검증 기준` (기본 `0.10`, `DLReadingTest.ini` 의 `VerifyPassScore` 로 저장). 값을 바꾸면 마지막 검증 결과를 추론 없이 바로 다시 판정합니다.
  낮추면 쓸린 글자를 더 통과시키지만 비슷한 모양의 다른 글자(6/G, 8/B 등)를 놓칠 위험이 커지므로,
  실제 쓸린 양품과 일부러 만든 불량 샘플로 정하는 것을 권장합니다.
- **ROI는 박스(인쇄 영역)마다 하나씩** 잡습니다. ROI 별로 같은 기대 문자열을 동시에 검증하고, 모든 ROI 가 OK 여야 전체 OK 입니다 (`검증 NG (2/3)` = 3개 중 2개 OK).
  ROI 없이 전체 이미지를 검증하면 기대 문자열마다 가장 잘 맞는 한 곳만 검증합니다.
- 병렬 실행: UI 스레드에서 ROI 별로 이미지를 먼저 잘라 둔 뒤(같은 Bitmap 을 여러 스레드가 동시에 만지지 않도록) ROI 마다 `Task.Run` 으로 검출+검증을 동시에 실행합니다.
  모델 세션(`YoloDetector`)은 하나를 공유하며 ONNX Runtime 의 `Run` 은 여러 스레드에서 동시에 호출해도 안전합니다.

실제 이미지로 확인한 결과 (박스 하나 ROI, 기준 0.10):

| 이미지 | 기대 문자 | 결과 |
|---|---|---|
| `real_2025-05-28_10-09-37.bmp` | `GWTB017P, 2030.03.16` | 9/10 OK (NG 1개는 `7` 점수 0.08 - 사람 눈으로는 정상, 모델이 이 폰트의 7 을 약하게 학습한 탓) |
| `real_2025-05-28_10-12-15.bmp` | `GWTB016P, 2030.03.12` | 10/10 OK |
| `real_2025-05-28_10-12-15.bmp` | `GWTB017P, 2030.03.16` (일부러 틀림) | 0/10 OK (전부 NG, 틀린 자리 점수 0.00) |

## 빌드 / 실행

1. Visual Studio 2022 (".NET 데스크톱 개발" 워크로드)에서 `DLReadingTest.sln` 열기
2. 빌드하면 NuGet 패키지(`Microsoft.ML.OnnxRuntime`)가 자동 복원되고, `Models\*.onnx` 가 출력 폴더로 복사됨
3. 실행 → `폴더 열기`(예: `samples`) → `ROI 추가` 후 테두리를 끌어 글자 영역으로 이동, 모서리로 크기 조절 → `읽기` / `검증`

### x64 / x86 (32비트)

솔루션에 프로젝트가 두 개 있습니다. 소스와 모델은 같고 플랫폼과 ONNX Runtime 버전만 다릅니다.

| 프로젝트 | 플랫폼 | ONNX Runtime | 실행 파일 |
|---|---|---|---|
| `DLReadingTest` | x64 | 1.32.0 (최신) | `DLReadingTest\bin\<구성>\net48\DLReadingTest.exe` |
| `DLReadingTest.x86` | x86 | **1.22.1** | `DLReadingTest.x86\bin\<구성>\net48\DLReadingTest_x86.exe` |

- ONNX Runtime NuGet 패키지는 **1.23.0 부터 win-x86 DLL 을 배포하지 않아서** x86 은 마지막 지원 버전 1.22.1 을 씁니다
  (NuGet 은 플랫폼별로 패키지 버전을 바꿀 수 없어 프로젝트를 나눴습니다). 같은 모델로 두 버전의 검증 결과가 같은 것을 확인했습니다.
- `DLReadingTest.x86` 은 `DLReadingTest` 폴더의 소스(`.cs`)와 `Models` 를 링크해서 씁니다. **코드 수정과 화면 디자인은 `DLReadingTest` 프로젝트에서** 하면 두 쪽에 모두 반영됩니다.
- 실행할 프로젝트는 솔루션 탐색기에서 `시작 프로젝트로 설정` 으로 고릅니다. 창 제목 끝에 `[x64]` / `[x86]` 이 표시됩니다.
- 32비트 DLL(구버전 카메라 SDK, 32비트 VisionPro 등)과 함께 써야 할 때만 x86 을 쓰고, 그 외에는 x64 를 권장합니다 (x86 은 다소 느릴 수 있음).
- Visual C++ 재배포 패키지(2015-2022)가 필요할 수 있습니다 (x64 / x86 각각 해당 플랫폼용).

## 모델 / 학습 (`training/`)

공개된 "알파벳/숫자 읽기" YOLO 모델이 따로 없어서, 글자 하나하나를 객체(36 클래스: `0-9`, `A-Z`)로 검출하도록
**YOLO26n**(Ultralytics, NMS-free, CPU/엣지 추론과 작은 객체에 강함)을 학습했습니다.
검출된 글자는 위→아래 줄, 줄 안에서 왼쪽→오른쪽 순서로 이어 붙여 문자열로 만듭니다.
`.` 은 읽지 않으므로 날짜 `2030.03.12` 는 `2030 03 12` 처럼 나옵니다(넓은 간격에 공백).

### 학습 데이터 (`gen_label.py`)

실제 카메라 이미지에 맞춰 만든 합성 데이터입니다.

- 제조번호는 영문 위주로 만들고, 헷갈리기 쉬운 글자(Q/C/G, I/J, M/W/V/N, P/B/R/F 등)는 3배 자주 넣습니다(날짜 때문에 숫자가 많이 학습되는 것을 보정).
- 영문 `O` 는 만들지 않습니다(숫자 `0` 만 학습). 클래스 번호 36개는 그대로라 기존 모델과 호환됩니다.

| 구성 | 비율 | 내용 |
|---|---|---|
| 실제 바탕 | 55% | `assets/plate_clean.png` (실제 이미지에서 영숫자만 지운 바탕) 20개 인쇄 위치에 무작위 제조번호/날짜를 흰색 단선 글씨, 넓은 자간으로 인쇄 |
| 합성 박스 | 30% | 어두운 박스 + 한글 라벨(`제조번호 :` `사용기한 :` 등, 라벨링 안 함) + 코드. 박스 개수/크기/밝기 다양 |
| 범용 | 15% | `gen_synth.py` 의 다양한 폰트/배경 (일반화용) |

- **움직임 번짐**(40%): 컨베이어 방향(가로)으로 글자 높이의 10~60% 길이만큼 끌림, 가끔 세로/사선으로 짧게
- **인쇄 문질림**(박스별 30%): 긁힌 줄무늬로 획 일부 지워짐, 한쪽으로 번진 꼬리, 잉크 빠짐
- 크롭: 박스 하나 / 이웃 박스 여러 개 / 전체 이미지
- 밝기, 감마, 노이즈, 블러, JPEG 압축

```bash
cd training
pip install ultralytics onnx onnxslim
python gen_label.py --out datasets/label --train 4000 --val 400                      # 데이터 생성
python train.py --data datasets/label/data.yaml --imgsz 640 --epochs 60 --device 0   # GPU 학습 (CPU 는 --device cpu)
```

- 학습이 끝나면 `best.onnx` 가 `DLReadingTest/Models/alnum_yolo26n.onnx` 로 복사됩니다.
- Windows 에서 실행하면 `C:\Windows\Fonts` 의 폰트(맑은 고딕 등)를 자동으로 사용합니다.
- **현장 이미지 추가 학습 (권장)**: 실제 이미지를 수십~수백 장 라벨링하면 인식률이 크게 올라갑니다.
  [Label Studio](https://labelstud.io), [CVAT](https://www.cvat.ai) 등에서 글자마다 박스를 그려 YOLO 형식으로 내보내고
  `data.yaml` 의 `train` 에 폴더를 추가하거나, `--weights <이전 best.pt>` 로 이어서 학습합니다.
  클래스 번호는 `0-9` → 0~9, `A-Z` → 10~35 입니다.
- 다른 제품/인쇄 형태가 생기면 `assets/` 에 새 바탕(인쇄를 지운 이미지)을 추가하는 방식으로 확장할 수 있습니다.

### 현재 포함된 모델의 성능

`Models/alnum_yolo26n.onnx`: YOLO26n, CPU 학습(512px), 입력 640px로 export. 결과에는 `LabelMap=O:0`(영문 O → 숫자 0)이 적용됩니다.

1. 합성 데이터 4,000장 20 epoch
2. 영문 비중을 높인 합성 데이터 4,000장 15 epoch
3. **현장 이미지 자동 라벨 추가 학습** 8 epoch (7 epoch 가중치 사용)
   - `samples/0*.jpg` 565장(`GWTC054P / 2031.07.07`) 중 시간순 앞 80%(452장)를 사용, 뒤 20%(113장)는 평가용으로 학습에서 제외
   - 인쇄 내용을 알고 있으므로 검증 결과(자리별 대응 박스)에 정답 글자를 붙여 자동 라벨링, 크롭 일부에 쓸림/번짐 효과 추가
   - 다른 글자를 잊지 않도록 합성 데이터 2,200장을 섞음
4. **균형 재학습** 5 epoch (4 epoch 가중치 사용): 현장 크롭 1,000장 + 현장 전체 이미지 80장 + 합성 4,000장(전체 글자 균형)
   - 3단계에서 현장에 없는 글자가 나빠진 것을 되돌리기 위해 합성 비중을 높임

**현장 이미지 평가** (학습에 쓰지 않은 113장 × 박스 10개, 박스마다 ROI, 기대 문자 `GWTC054P 2031.07.07`):

| 모델 | 박스 OK | 제조번호 줄 | 날짜 줄 |
|---|---|---|---|
| 이전 (합성만) | 53.4% (603/1130) | 91% | 58% (`7` → `2`/`5`) |
| 3단계 (현장 추가 학습) | 99.7% (1128/1131) | 99.8% | 99.7% |
| **현재 (4단계 균형 재학습)** | **99.7%** (1128/1131) | 99.8% | 99.7% |

- 남은 NG 3개는 평가 스크립트의 자동 박스 찾기가 ROI 를 좁게 잡은 경우이고, ROI 를 제대로 잡으면 둘 다 OK (점수 0.90 이상)

### 다른 모델 사용

`모델 열기` 로 다른 ONNX 를 불러올 수 있습니다. YOLO26(end-to-end 출력 `[1,N,6]`)과
YOLOv8 / YOLO11(출력 `[1,4+클래스,앵커]`) 형식을 자동 판별합니다.
클래스 이름은 Ultralytics 가 ONNX 메타데이터에 넣어 둔 `names` 를 쓰고,
모델과 같은 이름의 `.txt`(한 줄에 클래스 하나)가 있으면 그 파일을 우선 사용합니다.
